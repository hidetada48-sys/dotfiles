# answer-validator スキル

quiz-generator / mock-test-generator が生成したHTML問題集を受け取り、
全問の答えを3段階で自動検証して検証レポートを出力する。
ユーザーの操作は不要。ファイルのパスを渡すだけでよい。

**検証は 2A → 2B → 2C の3段階**（旧版では知識検証が「2D」と書かれ 2C が欠番だった。番号を詰めた）。
その前に**ステップ0で「答えが見えていないか」を調べる**。

---

## ステップ 0：答えの漏れ検査（必須・省略禁止）

答えが**正しいか**を見る前に、答えが**見えていないか**を見る。
生成側でも検査するが、通っていない版が回ってくることがあるので、ここが最後の関門になる。

```bash
python ~/.claude/skills/quiz-generator/references/check_leak.py <対象HTML>
```

漏れが1件でもあれば、**答えの検証に入る前に**その事実を報告して生成側へ差し戻す。
2026-08-08 には、出典の見出しと関連問題の設問文の両方に答えが書かれた問題集が
11節中10節で作られた（見出しに「◆ p.18 ⑧　亜寒帯の植生　タイガ」と書いていた）。

---

## ステップ 1：HTML の読み取り

対象のHTMLファイルを読み、以下を全問抽出する。
問題本文は `<section>`、巻末①解答一覧は `.ansrow`、巻末②解説は `.exp` に入っている
（体裁は `~/.claude/skills/quiz-generator/references/html-template.md` を参照）。

| 抽出対象 | 抽出先 |
|---------|--------|
| 問題番号 | `question_id`（例：大問1-(1)、p.13③(4)問1） |
| 問題文 | `question_text` |
| 解答一覧（巻末①）の答え | `answer_listed` |
| 解説（巻末②）に記載された答え | `answer_in_explanation` |
| 問題種別 | `type`（計算 / 知識 / 記述 / 選択 など） |

抽出後、問題一覧を内部テーブルとして保持し、以下のステップで検証する。

---

## ステップ 2A：解き直し検証

**目的：問題文と答えが対応しているかを独立した視点で確認する。**

全問について、`answer_listed` を伏せた状態で問題文だけを読み、Claudeが自力で答えを導く。

### 実施ルール

- 問題文の条件・制約を厳守して解く（「○語で答えよ」「語句を使って」など）
- 計算問題は必ずPythonで検証する（後述）
- 解き直した答えを `answer_rederived` として記録する
- `answer_listed` と `answer_rederived` を突合し、不一致は `✗` とする

### 計算問題のPython検証

```python
from fractions import Fraction
import math

def check(label, fn, expected):
    result = fn()
    status = "✓" if result == expected else f"✗ (got {result}, expected {expected})"
    print(f"{label}: {status}")

# 全計算問題を列挙して検証
# 例：
# check("大問2-(1)", lambda: 12 / 2, 6)
# check("大問3-(2)", lambda: Fraction(2,3) + Fraction(1,6), Fraction(5,6))
```

全問 ✓ を確認してから次のステップへ進む。

---

## ステップ 2B：転記突合検証

**目的：巻末①の解答一覧と巻末②の解説内の答えが一致しているか確認する。**

`answer_listed`（巻末①）と `answer_in_explanation`（巻末②）を全問突合する。

- 一致 → `転記: ✓`
- 不一致 → `転記: ✗`（両方の値を記録）
- 解説に答えの記載がない問題 → `転記: スキップ`

---

## ステップ 2C：知識検証

**目的：固有名詞・年号・数値・定義文を含む答えの正確性をweb_searchで確認する。**

対象：`type` が 知識 / 選択 / 記述 の問題のうち、以下を含むもの：
- 固有名詞（人名・地名・作品名・法律名 など）
- 年号・数値
- 定義文・説明文

### 実施ルール

1. 対象問題を列挙し、web_searchで各答えの正確性を確認する
2. 確認できた → `知識: ✓`
3. 教科書レベルの標準表現と齟齬がある → `知識: 要確認`（理由を付記）
4. 検索結果が見つからない・曖昧 → `知識: 要確認`（理由を付記）

---

## ステップ 3：フラグ集約

各問題について、2A・2B・2Cの結果を集約して最終フラグを決定する。

| 条件 | 最終フラグ |
|------|-----------|
| 2A・2B・2C すべて ✓ | ✓ |
| 2A または 2B に ✗ あり | ✗ |
| 2C に 要確認 あり（2A・2Bは✓） | 要確認 |

---

## ステップ 4：検証レポートの出力

以下の形式でチャットに出力する。

```
【答え検証レポート】生成元：quiz-generator / mock-test-generator（判断して記載）

─────────────────────────────
✓ 問題なし：XX問
✗ 要修正　：XX問
要確認　　：XX問
─────────────────────────────

【✗ 要修正】
大問1-(2)
  解き直し：設計の答え「12cm」→ 解き直し「6cm」
  修正案：答えを「6cm」に変更する

大問3-(1)
  転記ミス：巻末①「江戸幕府」→ 巻末②「室町幕府」
  修正案：巻末②を「江戸幕府」に統一する

【要確認】（ヒデさんが目視確認してください）
大問2-(3)
  知識：「1635年」→ web_searchで確認できず。正確な年号をご確認ください。

【✓ 問題なし】
大問1-(1)、大問1-(3)、大問2-(1)、大問2-(2)　…（以下略）
─────────────────────────────
```

---

## ステップ 5：✗ があった場合の案内

✗ がある場合、チャットに以下を表示する。

```
✗ の問題があります。
quiz-generator / mock-test-generator に以下を貼って修正を依頼してください：

---
【answer-validator 検証結果】
以下の問題に誤りがあります。修正してHTMLを再出力してください。

[✗の問題ごとの修正案をここに列挙]
---

修正後のHTMLを再度 answer-validator に通すことを推奨します。
```

✓ のみの場合：
```
全問題に問題はありませんでした。このHTMLをそのまま使用できます。
```

## ステップ 6：検証レシートの発行（✗が0件のとき必須・省略禁止／2026-08-17 新設）

**スタンプの前に、2A/2B/完全性の“証拠物（レシート）”を機械で残す。**
2026-08-17、Claude が answer-validator を実際には起動せず「検証した」とだけ言って
スタンプを押し配信した（証拠物ゼロ）。これを封じるため、レシート無しではスタンプできない。

全問 ✓（✗0件）にしたら、独立解答（2A）を**全 mondai_id ぶん**列挙したファイル
`rederived.json` を作り（`{ "1-【1】": {"a":"蘇我氏","twoC":"ok"}, ... 全問 ... }`）、次を通す：

```bash
python3 ~/.claude/skills/quiz-generator/references/av_report.py <HTML> <log/出題履歴.json> --rederived <rederived.json>
```

- **2B**（巻末①＝巻末②）と**完全性**（巻末①が log の全 id を覆う／件数一致）を機械で判定。
- **2A**は短答型（知識・選択・穴埋め・計算・並べかえ）を巻末①と機械突合。記述・図表型は
  照合不可のため「要目視」として**必ず列挙だけはさせる**（1問でも欠けると all_pass にならない）。
- 結果を `<html>.avcheck.json`（HTMLの sha256 入り）に書く。all_pass でなければ非ゼロ終了。

## ステップ 7：合格スタンプの発行（✗が0件のとき必須・省略禁止／2026-08-13）

レシートが all_pass になったら、**最後に必ず合格スタンプを発行する**。これがないと配布できない：

```bash
python3 ~/.claude/skills/quiz-generator/references/av_stamp.py <検証したHTML> <log/出題履歴.json> --problems <問題数>
```

- スタンプは**検証したHTMLの sha256（中身の指紋）**を刻んで `<html>.av.json` に保存する。
- **av_stamp は `<html>.avcheck.json`（レシート）の実在・sha一致・all_pass・全問列挙を要求する。**
  無ければスタンプを発行しない＝**「検証した」と言うだけで証拠を残さず配信、が物理的にできない**
  （2026-08-17 に answer-validator を起動せず押した叱責を受けて機械ゲート化）。
- **`publish_to_drive.sh` は、配信するHTMLの sha256 とスタンプが一致し status=pass でなければ配信を拒否する。**
  ＝**answer-validator を飛ばして配信することも、検証後にHTMLを直して配信することも物理的にできない**
  （2026-08-13 に answer-validator を飛ばした叱責を受けて機械ゲート化）。
- ✗があるうちはスタンプを発行しない（修正→再検証→✗0件になってから発行）。
- スタンプ発行時に check_leak／check_pitfalls を再実行し、落ちていればスタンプを書かない（二重の安全）。
