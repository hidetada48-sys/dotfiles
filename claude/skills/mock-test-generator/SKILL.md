# mock-test-generator スキル

問題集の画像と教科情報から、単元全体の模擬テスト（既定100点・50分・本番形式）を生成する。
quiz-generatorのJSONに`visual_emphasis`が含まれている場合は**画像なしで動作可能**。

**出力はHTML1本。** docx・PDFは作らない（印刷はブラウザの「印刷 → PDFに保存」）。
体裁の正典は `~/.claude/skills/quiz-generator/references/html-template.md`（quiz-generator と共通）。
**生成前に必ずこのテンプレートを読むこと。**

---

## ステップ 1：インプット収集

| 必要なもの | 形式 | 必須 |
|-----------|------|------|
| quiz-generator の JSON ログ | JSONファイル | △（あれば） |
| 問題集のページ写真 | 画像（複数可） | △（JSONにvisual_emphasisがなければ必要） |
| 教科名 | テキスト | ○ |
| 出題範囲 | テキスト（ページ指定 or 全ページ） | ○ |
| 前回の出題履歴 JSON | JSONファイル | △（2回目以降はあれば） |

### インプット受け取り時の確認フロー

```
① JSONを受け取る
      ↓
② JSON に visual_emphasis があるか確認する
   ある → 「画像は不要です。このまま進めます。」と伝える
   ない → 「画像をアップロードしてください。」と促す
      ↓
③ JSONがない場合は「JSONログはありますか？」と確認する
   ある → アップロードを促す
   ない → 画像のアップロードを促してそのまま進む
      ↓
④ 「前回の出題履歴JSONはありますか？」と確認する
   ある → アップロードを促す
   ない → 初回として進む
```

## ステップ 2：コア項目の特定

以下の **3軸を同等の重みで** 評価し、コア項目リストを作成する。

### ① 視覚的強調（JSONまたは画像から取得）

以下の優先順位で視覚強調情報を取得する。

| 状況 | 取得方法 |
|------|---------|
| JSONに`visual_emphasis`がある | JSONの`emphasis_points`・`key_sentences`・`can_do`を読む（画像不要） |
| JSONにないが画像がある | 画像から直接読み取る（教科・出版社固有の強調表現に注目） |
| 両方ある | JSONを優先し、画像で補完する |

**渡されたJSONが出題範囲を覆っているかを最初に確かめる（必須）。**
`pages_scanned` を出題範囲と突き合わせ、**足りなければそこで止めて不足ページを求める**。
JSONの中で数が揃っていても、読まれたページ数自体が足りないことがある
（2026-08-08 に、7枚の範囲に対して2見開き分しか入っていないJSONが作られた）。
**間違い記録は3軸のうちの1つにすぎない。模擬テストは出題範囲全体から作る。**

**【必須手順】JSONに`visual_emphasis`がある場合：**
1. 全ページの`emphasis_points`と`key_sentences`を**ページ順に全件列挙**する
2. 列挙した全項目をコア項目の候補としてリストアップする
3. ②③の軸と照合して重み付けする
4. **①で列挙した項目がコア項目リストに漏れなく反映されているか最終確認する**
   （②の教科知識だけで構成してはならない）

※ この手順を省略してコア項目リストを出力してはならない。

**画像から読み取る場合：**

**読む前に必ず前処理する（省略禁止）。** スマホ写真はそのままでは読めない
（安全フックが1ファイル100KB超をブロックする）。しかも**向きがEXIFでは直らない**。

```bash
# ① 向きを確認する
python ~/.claude/skills/quiz-generator/references/prep_images.py --thumb <作業フォルダ> <写真...>
# ② 回転とページ番号を指定して分割・圧縮する
python ~/.claude/skills/quiz-generator/references/prep_images.py <作業フォルダ> "写真@90=p18-19" ...
```

**手順は quiz-generator のステップ0（0-1〜0-4）と同じ。**
向きを目で決める・ページ番号を読み取ってリネームする・読み取り結果を読み上げて確認を取る、
の3点を飛ばさないこと。

前処理後、教科・出版社によってレイアウトが異なるため、ルールを固定せず
「このテキストでは何が重要事項として強調されているか」を判断する。
囲み・太字・色付き・繰り返しパターン・まとめ欄・ポイント欄など
テキスト固有の強調表現に注目する。

### ② Claudeの教科知識による重要度判断
テキストの強調に依存せず、その単元・内容について
「一般的に重要とされる概念・スキル」をClaudeが独自に判断する。
テキストに強調がなくても、教科の一般論として外せない項目は必ず含める。

### ③ JSONログの間違い記録
quiz-generatorが出力したJSONが渡された場合：
- **JSONにエントリが存在すること自体が「間違えた」の証拠**
- `key_point` を読み込みコア項目と照合する
- `wrong_count` が 2以上 → **必出**（必ず1問以上含める）
- `wrong_count` が 1　　→ **重要**（重要項目として含める）
- エントリが存在しない項目 → ①②の2軸のみで判断

JSONがない場合はこの軸はスキップする。

## ステップ 3：作成前に確認する項目

コア項目特定後、問題生成前に1回だけ質問する。

```
① 学年・クラス名を教えてください。（テスト用紙の見出しに使います。省略可）

② 満点と試験時間はどうしますか？
   既定は「100点・50分」です。
   範囲が狭い単元では小さくしてかまいません（例：国語の文法3見開き → 60点・30分）。

③ 記述問題の量はどうしますか？
   ・多め　（思考力・表現力重視）
   ・標準　（バランス型）
   ・少なめ（知識・技能確認重視）

④ 【JSONにdifficultyフィールドがある場合のみ表示】
   テストの難易度レベルはどうしますか？
   ・基礎　（基本語句の穴埋め・選択中心 / 知識・用語の定着確認）
   ・標準　（穴埋め・選択・記述をバランスよく混在 / 理解度の総合確認）
   ・応用　（記述・比較・思考力問題中心 / 説明力・応用力の確認）
```

### 満点・試験時間の扱い（必須）

②の回答を **`TOTAL_POINTS` / `TIME_LIMIT`** として保持し、以降のすべての工程で使う。
**この2つを固定値として扱ってはならない**（ステップ5.5の検算もこの変数で行う）。

- 回答が無ければ既定の 100点・50分 を使う
- 一度決めたら、構成案・検算・見出し・出題履歴JSONで**同じ値を使い回す**

### difficultyの反映ルール

| 選択 | difficulty=0の項目 | difficulty=1の項目 |
|------|-------------------|-------------------|
| 基礎 | 全て出題対象 | 1〜2問のみ（補足として） |
| 標準 | バランスよく混在 | バランスよく混在 |
| 応用 | 1〜2問のみ（導入として） | 全て出題対象 |

※ JSONにdifficultyフィールドがない場合は③を表示せず、標準として扱う。

## ステップ 4：承認ターン①　コア項目リストの確認

以下の形式で提示し、ユーザーの承認または修正指示を待つ。
**承認なしに次のステップへ進まない。**

### 前回履歴がない場合（初回）

```
【コア項目リスト】（教科：〇〇　範囲：〇〇）
難易度レベル：〇〇（基本語句の穴埋め・選択中心 / 知識・用語の定着確認）
　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　 ※levelに応じた説明文を毎回付記する

■ 必出項目（JSON wrong_count 2以上 / 3軸すべてで重要と判断）
  - ...

■ 重要項目（3軸のうち2軸以上で重要と判断）
  - ...

■ 補足項目（出題余地があるもの）
  - ...

追加・削除・変更があれば教えてください。
承認後にテスト構成の設計に進みます。
```

### 前回履歴がある場合（2回目以降）

必出・重要・補足の**全項目を再掲**し、全項目に前回との差分を付記する。

```
【コア項目リスト】（教科：〇〇　範囲：〇〇）
難易度レベル：〇〇（〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇〇）
　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　 ※levelに応じた説明文を毎回付記する

■ 必出項目
  - 〇〇　※前回：記述　→ 今回：選択に変更予定
  - 〇〇　※前回出題なし　→ 今回：新規出題

■ 重要項目
  - 〇〇　※前回：穴埋め　→ 今回：記述に変更予定
  - 〇〇　※前回：選択　→ 今回：穴埋めに変更予定
  （以下すべて再掲）

■ 補足項目
  - 〇〇　※前回：記述　→ 今回：選択に変更予定
  - 〇〇　※前回出題なし　→ 今回：新規出題
  （以下すべて再掲）

追加・削除・変更があれば教えてください。
承認後にテスト構成の設計に進みます。
```

#### 差分付記のルール
- 前回履歴にある項目：`※前回：〇〇形式　→ 今回：〇〇形式に変更予定`
- 前回履歴にない項目：`※前回出題なし　→ 今回：新規出題`
- 同じ項目を同じ形式で出題する場合でも必ず付記する（省略しない）
- **前回と全く同じ形式・切り口の問題を出題してはならない**
  （同一項目は切り口・形式・問い方のいずれかを必ず変える）

## ステップ 5.5：配点の機械検算（必須・省略禁止）

**過去に「宣言100点／実際92点」「宣言15点／実際13点」の配点バグが複数回発生している。**
小問を設計したら、HTML生成前にPythonで必ず検算する。

**満点はステップ3で決めた `TOTAL_POINTS` で検算する。100を直接書かない。**
（100固定にすると、60点のテストを作るときに検算そのものが素通りしてしまう）

```python
# ステップ3で決めた値をそのまま入れる（既定は100点・50分）
TOTAL_POINTS = 100
TIME_LIMIT = 50

# 大問ごとの「宣言配点」と「小問配点の内訳」を突合する
daimon_declared = {1: 20, 2: 25, 3: 20, 4: 15, 5: 20}
detail = {
    1: [8, 2, 2, 4, 4],   # 【1】〜【5】の配点
    2: [8, 6, 4, 2, 5],
    # ...全大問分
}
daimon_time = {1: 10, 2: 12, 3: 10, 4: 8, 5: 10}   # 目安時間

total = 0
for d, items in detail.items():
    s = sum(items); total += s
    print(f"大問{d}: 実際{s}点 / 宣言{daimon_declared[d]}点",
          "OK" if s == daimon_declared[d] else "NG")
print("合計:", total, "/", TOTAL_POINTS)
assert total == TOTAL_POINTS, f"合計が{total}点です。{TOTAL_POINTS}点に修正すること"

t = sum(daimon_time.values())
assert t == TIME_LIMIT, f"目安時間の合計が{t}分です。{TIME_LIMIT}分に修正すること"
```

- 「各1点」「各2点」の設問は、**空欄・小問の個数を数えて**内訳に反映する
- 目安時間の合計が `TIME_LIMIT` になることも同時に確認する
- NGが出た場合は**問題を追加または配点を振り直し**、`TOTAL_POINTS` になるまで繰り返す

## ステップ 6：HTML 生成前の答え検証（必須・省略禁止）

生成スクリプトを書く前に、以下の検証を必ず実施する。
**この手順を省略してHTMLを生成してはならない。**

### 数学・理科（計算あり）

```python
# Pythonで全計算を機械的に検証する
# fractions.Fraction を使って分数計算も正確に処理する
# 計算結果とハードコード予定の答えを突合し、不一致は修正してから埋め込む
from fractions import Fraction
import math

# 例：
# check("【3】⑴", lambda: 9 + (-15), -6)
# check("【5】⑺", lambda: Fraction(-2,3) / Fraction(-4,9), Fraction(3,2))
```

検証スクリプトを実行し、全問 ✓ を確認してからHTML生成に進む。
✗ が出た場合は答えを修正し、再度全問 ✓ になるまで繰り返す。

### 理科・社会・国語・英語（知識・語句）

計算ではなく知識の正確性が問題になるため、以下を実施する。

```
① 答えに固有名詞・数値・年号・定義文が含まれる場合、web_searchで正確性を確認する
② 教科書レベルの標準的な表現と一致しているか照合する
③ 確認できた記述のみ埋め込む。曖昧なものは問題ごと差し替える
```

### 検証完了の宣言

検証後、チャットに以下を出力してからHTML生成に進む。

```
【答え検証完了】
配点検算：全大問 ✓　合計TOTAL_POINTS点・TIME_LIMIT分
数学計算：XX問 全問 ✓（またはX問修正済み）
知識確認：XX項目 web_search確認済み（知識問題がある場合のみ）
→ HTML生成に進みます。
```

## ステップ 7：HTML 生成

**生成前に `~/.claude/skills/quiz-generator/references/html-template.md` を必ず読む。**
体裁の正典はそちらで、このステップはその使い方だけを書く。
外部ライブラリは要らない（Pythonの標準機能で文字列を組み立てて書き出す）。

作業用の一時フォルダに書き出し、体裁を確認してからDriveの教材フォルダへ `rclone copy` する。
**リポジトリ内には置かない**（私用の教材のため）。

### ドキュメント構成

```
テストヘッダー
  教科名・単元名・学年クラス・氏名欄・日付欄・得点欄（　/TOTAL_POINTS）・試験時間（TIME_LIMIT分）

大問1〜5
  ・大問番号・タイトル・配点を明記
  ・リード文（問題の指示）
  ・各小問（番号付き）
  ・解答欄（形式に応じて穴埋め・罫線・ボックス）
  ・図表を使う問題は下記「図・表・地図・写真の扱い」に従う

巻末①　解答一覧（答えのみ・採点用）
巻末②　解答・解説（各問の詳細解説）
```

### 図・表・地図・写真の扱い（必須）

**図・表・地図・写真をテストに埋め込むことは禁止する（著作権上の理由）。**
新しい図を生成して代用することもしない。
**元の問題文をそのまま流用することも禁止する。**

| 分類 | 条件 | 処理 |
|------|------|------|
| **A** 自己完結型 | 図がなくても解ける | 図に依存しない形で出題する（第一選択） |
| **B** 文章化 | 図が必須だが、内容を文章で説明できる | 図の情報を問題文に書き下して出題する |
| **C** 原本参照 | 文章化できない | 原本を参照させ、**問いは必ずずらす** |

**模擬テストではA・Bを優先する。**
模擬テストは50分の本番形式で解くものであり、ワークを開かせるのは望ましくない。
実際、これまでの模擬テスト（歴史・理科・英語・数学）は全問がA・Bで成立している。
四大文明の文字は「川：（　）文字：（　）」、三大宗教の発祥地は「① インド　② パレスチナ」
のように文章化すれば十分機能する。

**分類Cを使う場合**
問題文の直前に赤字（`color: 'C00000'`）で注記を入れ、
**元の問題と同じ設問・同じ答えにならないよう問いをずらす。**

```
※ワークP.◯の図／地図／写真を見て答えなさい
```

ずらし方は quiz-generator の同項目と同じ（答えの対象を変える／順序・比較を問う／
一部に絞って深掘りする／理由・特徴を問う）。
分類Cを使った問題は出題履歴JSONに `"figure_dependent": true` を付与し、
チャットでも一覧で報告する。

### 体裁ルール（必須）

**レイアウト目的の表組み（`<table>`）を使ってはならない。**
氏名欄・得点欄・解答欄はテンプレートの `.namebar` / `.ans` を使う。

| 用途 | 使うもの | 禁止 |
|------|---------|------|
| 氏名・日付・得点欄 | `.namebar` | `<table>` |
| 大問の見出し | `h2`（下に紺の罫線） | 背景ベタ塗り |
| 解答欄 | `.ans` の中に `<i>` を必要な数だけ | `<table>` / `<br>` の連打 |
| 原本参照の注記 | `.src`（赤字） | 図の埋め込み |
| 大問の区切り | `<section>`（印刷時に途中で切れない） | 手動の改ページ調整 |

問題文は写真から起こしたテキストなので、**必ず `html.escape()` してから埋め込む。**

### 生成後の検査（必須・省略禁止）

**① 答えの漏れを機械で調べる。** テストで答えが見えていたら意味がない。

```bash
python ~/.claude/skills/quiz-generator/references/check_leak.py <出力HTML>
```

**漏れが1件でもあれば提示してはならない。** 言い換えて消し、再生成して0件にする。
特に**大問の見出し**（「大問3　地中海性気候」など）は答えを書きやすい。
見出しには**出題範囲の単元名だけ**を書く。

機械が拾えないのは設問文のヒント（選択肢を絞る書き方）。これは自分で全設問を読む。

**② 体裁を目で見る。**
書き出したHTMLをブラウザで開き、**巻末の解答・解説まで通して**崩れていないことを確認する。
印刷が必要なときはブラウザの「印刷 → PDFに保存」を使う。A4用のCSSはテンプレートに入っている。

### 問題形式の選択肢（教科・記述量設定に応じて組み合わせる）

| 形式 | 内容 | 向いている教科 |
|------|------|--------------|
| 語句穴埋め | （　）に語句を書く | 全教科 |
| 選択 | ア〜エから選ぶ | 全教科 |
| 計算 | 計算欄付き、答えを書く | 数学・理科・時差 |
| 並べかえ | 語を並べて文を作る | 英語 |
| 書きかえ | 指示にしたがって文を変える | 英語 |
| 英作文 | 日本語→英語 | 英語 |
| 記述 | 理由・説明を書く | 社会・理科・国語 |
| 読解 | 文章・対話文を読んで答える | 英語・国語 |
| 図表読み取り | 資料を見て答える | 社会・理科 |

## ステップ 9.5：answer-validator からの修正依頼への対応

### トリガー
- 「answer-validator 検証結果」を含むテキストが渡された場合
- 「✗の問題を修正して」「検証結果に基づいて修正して」などの言及がある場合

### 処理手順

**① 修正内容の確認**
渡された検証結果から ✗ の問題を全件抽出し、以下を確認する。

| 確認項目 | 内容 |
|---------|------|
| 問題番号 | どの大問・小問が対象か |
| 修正種別 | 解き直し不一致 / 転記ミス のどちらか |
| 修正案 | answer-validator が提示した修正内容 |

**② 修正の適用**

- **解き直し不一致（答えが間違い）**：問題文・答え・解説を修正案に基づいて修正する
- **転記ミス（巻末①②の不一致）**：巻末①を正として巻末②を修正する

**③ HTML の再生成**

修正を適用してHTMLを再生成し、同じ場所に上書き保存する。
ファイル名は元のファイル名を維持する（`_fixed` などのサフィックスは付けない）。
**Driveへコピー済みの場合は、そちらも上書きする**（古い版が残らないようにする）。
出題履歴JSONは変更しない（答えの修正は出題履歴に影響しないため）。

**④ 再検証の案内**

```
修正済みHTMLを出力しました。
answer-validator で再検証することを推奨します。
```

## wrong_count の運用ルール

- JSONにエントリが存在する = 間違えたことがある問題
- JSONにエントリが存在しない = 間違えた記録がない問題
- wrong_count は quiz-generator が初回生成時に 1 で作成し、再生成のたびに +1 する
- mock-test-generator はこの値を読み取るだけで書き込まない
