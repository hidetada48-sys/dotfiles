# quiz-generator スキル

問題集の写真と間違えた問題番号から、類似・関連問題のHTML問題集を生成する。

**出力はHTML1本。** docx・PDFは作らない（印刷はブラウザの「印刷 → PDFに保存」）。
体裁の正典は `~/.claude/skills/quiz-generator/references/html-template.md`。
**生成前に必ずこのテンプレートを読むこと。**

---

## ステップ 0：写真の受け入れ（必須・省略禁止）

**このステップは Claude が全部やる。ユーザーは撮った写真を置くだけでよい。**
以前はここを人手でやっていた（向きを直す・ページ番号を読む・ファイル名を付ける）が、
skillの中に取り込んだ。

### 0-1　向きを決める

スマホの見開き写真は**EXIFでは向きが直らない**。撮り方でばらつくので機械任せにしない。

```bash
python <このskill>/references/prep_images.py --thumb <作業フォルダ> <写真...>
```

縮小版が出るので**必ず目で見て**1枚ずつ回転を決める。実測の目安（2026-08-08 地理）：

| EXIF補正後の形 | よくある向き | 指定 |
|---|---|---|
| 縦長（例 3000x4000） | 本を横倒しに置いて撮った | `@90`（反時計） |
| 横長（例 4000x3000） | 上下が逆さま | `@180` |

**目安であって規則ではない。** サムネイルで文字の向きを確かめてから決める。

### 0-2　分割して読める大きさにする

安全フックが1ファイル100KB超をブロックするため、そのままでは読めない。

```bash
python <このskill>/references/prep_images.py <作業フォルダ> "写真A@90" "写真B@180" ...
```

見開きを左右に割り、さらに上下に割って98KB未満に収める。
**カラーのまま扱う**（グレーにすると赤い手書きの印が印刷の線と区別できなくなる。
しかも実測ではカラーの方が小さい）。

### 0-3　ページ番号を読み取って確定する

出力を読み、**ページ隅のノンブル・単元名・教科書対応ページ**からページ番号を割り出す。
割り出したら `=p18-19` を付けて 0-2 をやり直し、正しい名前のファイルにする。

ページ番号が確定しないまま問題を作ってはならない（ページ取り違えは実際に起きている）。

### 0-4　読み取り結果を読み上げて確認を取る（エコーバック・必須）

```
写真7枚を次のとおり読みました。違っていたら教えてください。

  1枚目 → p.18-19「寒帯・亜寒帯・温帯の土地に暮らす人々」（教科書P.36〜41）
  2枚目 → p.20-21「乾燥帯・熱帯の土地・高地に暮らす人々」（教科書P.42〜47）
  ...
```

**ここで止まって返事を待つ。** 勝手に先へ進まない。

## ステップ 1：間違えた問題を特定する

受け取り方は2通り。**どちらでもよい。**

### 1-A　テキストで受け取る（例：p.13 ③(4)、p.7 ②(2)）

そのまま使う。確認は不要。

### 1-B　写真の赤い印から読み取る

**印の付け方は教科・本人によって違う。** 決めつけず、まず何の印かを見る
（地理では「空欄の丸数字を通る赤い斜線1本＝1問」だった）。

**手順は3段。機械→目視→本人確認の順で、どれも飛ばさない。**

```bash
python <このskill>/references/find_redmarks.py <ページ画像...>
```

**① 機械が候補を絞る。** 赤くて線状で紙の上にあるものを拾う。見落としを防ぐのが目的。

**② Claude が目で判別する。** 候補の座標を切り出して拡大し、手書きか印刷かを見る。
**機械の出力をそのまま信じてはならない。** 実際に、印刷の見出し・★・国旗・
地図の国境線・雨温図の折れ線・イラストがすべて候補に入った（2026-08-08 地理）。

**③ 読み取った番号を本人に読み上げて確認を取る（エコーバック・必須）。**
番号だけでなく**問題文の書き出しを添える**。番号だけでは合っているか判断できない。

```
赤い印から、間違えた問題を次のとおり読み取りました。違っていたら教えてください。

  p.18「寒帯・亜寒帯・温帯の土地に暮らす人々」
    ④ 針葉樹林の…／⑧ 永久凍土の…／⑩ 建物を高床に…／⑬ 白夜と…／⑯ 混合農業の…
  p.20「乾燥帯・熱帯の土地・高地に暮らす人々」
    ③ オアシスの…／④ 遊牧の…／…

  印が見つからなかったページ：p.19、p.21〜24
```

**印が無かったページも必ず並べて言う。** 見落としたのか本当に無いのかを本人が判断できる。

**ここで止まって返事を待つ。**

**判読不明な問題文がある場合は作成前に確認する（事後修正しない）。**

## ステップ 2：作成前に必ず聞く3つの質問

インプットが揃ったら、問題生成の前に以下を確認する。

### Q1：1問あたりの生成数
```
1問あたり何問生成しますか？
デフォルトは「類似1問＋関連（応用）1問」です。
```

### Q2：難易度設定
```
難易度を設定してください。
オリジナルの問題を 0 として：

  -1　易しめ（穴埋め・選択肢あり、用語確認レベル）
   0　同等（類似問題の基本設定）
  +1　やや応用（語句指定あり記述・条件追加）
  +2　発展（複数知識の組み合わせ・自由記述）

類似問題と関連問題で別々に設定できます。
デフォルト：類似＝0、関連＝+1
```

### Q3：出力ファイル名（任意）
```
ファイル名はありますか？（省略可、省略時は自動命名）
```

## ステップ 3：画像の読み取り（2段階で同時実施）

前処理と向きの決定は**ステップ0で済んでいる前提**。まだなら先にステップ0へ戻る。

- ファイル名の `a` が上半分、`b` が下半分。境界は40px重ねてあるので、境目の行は消えない
- 「※圧縮の下限」と出たものは、読んだときに判読できるか意識して確認する

### 3a：全ページの視覚強調を読み取る（JSON用）★飛ばしやすい

**渡された写真は1枚残らず読む。** 間違えた問題があるページだけではない。

**なぜ全ページなのか**：この `visual_emphasis` が **mock-test-generator の主食**になる。
模擬テストは**出題範囲全体**から作るもので、間違えた箇所はそこに重みを乗せるだけ
（コア項目の3軸のうち間違い記録は3分の1）。
解説書§4いわく「visual_emphasis が最重要。これがあれば模擬テストは写真なしで作れる」。
**ここを間引くと、範囲の一部しか出ないテストになる。**

（2026-08-08 に7枚渡されて2見開きしか読まず、範囲の3分の1しか覆わない log.json を作った）

**枚数の突き合わせ（必須）**：JSONを書く前に
**「渡された写真の枚数」と「`pages_scanned` が覆うページ数」が合っているか**を数えて確かめる。
`pages_scanned` と `visual_emphasis` の数が一致していても、
**読んだページ数そのものが足りなければ意味がない**（両方2件なら整合チェックは通ってしまう）。

以下を読み取ってJSONの`visual_emphasis`に記録する。
問題文を1問1問読む必要はない。テキスト固有の強調表現に集中する。

- 単元名・CAN-DO・基本文（太字・色付き・囲みになっているもの）
- ポイント・まとめ・チェック欄の内容
- 繰り返し登場するパターン・問題形式

### 3b：指定問題の問題文を判読する

- 間違えた問題番号のリストに対応する問題文のみ判読する
- 図・表・グラフを使う問題は「p.XX の図〇〇を参照」と記録する（図は埋め込まない）
- 不明確な箇所は**この段階で**ユーザーに確認する

## ステップ 4：類似・関連問題の設計ルール

### 類似問題（デフォルト難易度 0）
- 元の問題と同じ形式・スキルを問う
- 数値・地名・人物名・条件などを変更する
- 元の問題文をそのまま流用しない

### 関連（応用）問題（デフォルト難易度 +1）
- 同じテーマ・概念を別の角度から問う
- 「なぜ？」「どう違う？」など思考を要する記述を含める
- 指定語句を使った記述問題を積極的に採用する

### 難易度ガイドライン

| レベル | 特徴 |
|--------|------|
| −1 | 選択肢あり、穴埋め、用語確認のみ |
| 0 | 元問題と同等の思考量・形式 |
| +1 | 語句指定あり記述、条件追加、複合的な計算 |
| +2 | 自由記述、複数概念の統合、資料読み取り＋考察 |

### 教科別の注意点
- **計算問題**（数学・理科・時差など）：数値を変えて同じ解法で解けるものを作る
- **記述問題**（社会・国語）：語句指定は毎回変える
- **選択問題**：選択肢の構成（正答の位置・ダミーの質）を意識する

## ステップ 4.2：図・表・地図・写真を使う問題の扱い（必須）

**大前提1：図・表・地図・写真を問題集に埋め込むことは禁止する（著作権上の理由）。**
新しい図を生成して代用することもしない。

**大前提2：元の問題文をそのまま流用することは禁止する。**
これは類題集の根幹であり、図を使う問題であっても例外を認めない。
ワーク原本を参照させる場合、生徒はワークを開くため、
**同じ問題文にすると本人が書き込んだ答えがそのまま目に入る。**

### 判定フロー

```
その問題は図がないと解けないか？
  ├─ NO（図は補助的） ──→ 【分類A】図に依存しない新問題を作る
  └─ YES（図が必須）
        ├─ 図の内容を文章で説明できる → 【分類B】文章化して自己完結型にする
        └─ 文章化できない　　　　　　 → 【分類C】原本参照＋問いをずらす
```

### 【分類A】自己完結型に作り替える（第一選択）
図に依存しない形に問題を再設計する。通常の類似・関連問題として扱う。

### 【分類B】図の内容を文章化する
図から読み取れる情報を問題文に書き下し、図がなくても解ける形にする。
例：「右の地図中Aの地域」→「赤道付近に位置し、一年中高温多雨な地域」

### 【分類C】原本参照＋問いをずらす

図そのものを見せる必要があるが文章化できない場合に採用する。
**図は原本を見せ、問いは必ず新しく作る。**

問題文の直前に赤字（テンプレートの `.src` クラス）で注記を入れる。

```
※ワークP.◯の図／地図／写真を見て答えなさい
```

**問いのずらし方（同じ図から別の答えを引き出す）**

| ずらし方 | 例 |
|---------|---|
| 答えの対象を変える | 「Ⅰ〜Ⅳの文字名を答えよ」→「Ⅰ〜Ⅳの文明がおこった川名を答えよ」 |
| 順序・比較を問う | 「A〜Cは何教か」→「A〜Cを成立が古い順に並べよ」 |
| 一部に絞って深掘り | 「A〜Cを選べ」→「Bの宗教の開祖と聖典を答えよ」 |
| 理由・特徴を問う | 「Dはどれか」→「Dがそう判断できる理由を書け」 |

**禁止事項**
- 元の問題文と同一・ほぼ同一の設問にすること
- 元の解答と同じ答えになる設問にすること
- 同じセクションの関連問題と答えが重複すること

### どうしてもずらせない場合

図の要素が少なく、どう問うても元と同じ答えにしかならない図が稀にある。
その場合は**独断で流用せず、ユーザーに次を提示して判断を仰ぐ**。

```
【判断をお願いします】
p.◯ ◯◯の図は、どう問いを変えても元の問題と同じ答えになります。
　ア この問題は出題しない（他の問題で代替する）
　イ 元の問題のまま出題する（ワークに答えが残っている点は了承のうえ）
```

### 分類Cを使った場合の必須処理
- ログJSONの該当problemに `"figure_dependent": true` を付与する
- チャットで「原本参照にした問題」と**どうずらしたか**を一覧で報告する

### 判定の報告
ステップ3bの判読結果を提示する際、図を使う問題については
**A／B／C のどれで処理するかを明記してユーザーの確認を取る。**

## ステップ 5：HTML 生成

**生成前に `~/.claude/skills/quiz-generator/references/html-template.md` を必ず読む。**
体裁の正典はそちらで、このステップはその使い方だけを書く。
外部ライブラリは要らない（Pythonの標準機能で文字列を組み立てて書き出す）。

### ドキュメント構成

```
見出し
  タイトル・氏名欄・日付欄

問題セクション（出典ごとに <section>）
  出典ラベル（例: ◆ p.13 ③(4) 等時帯と時差）
  類似問題ラベル（青）＋問題文＋解答欄
  関連問題ラベル（オレンジ）＋問題文＋解答欄

巻末①　解答一覧（答えのみ・全問一覧）※改ページしてから
巻末②　解説（問ごとの詳細解説）※改ページしてから
```

### 体裁ルール（必須）

**レイアウト目的の表組み（`<table>`）を使ってはならない。**
氏名欄・解答欄はテンプレートの `.namebar` / `.ans` を使う。

| 用途 | 使うもの | 禁止 |
|------|---------|------|
| 氏名・日付欄 | `.namebar` | `<table>` |
| 解答欄 | `.ans` の中に `<i>` を必要な数だけ | `<table>` / `<br>` の連打 |
| 出典の見出し | `h2`（下に紺の罫線） | 背景ベタ塗り |
| 類似／関連ラベル | `.tag.sim` / `.tag.rel` | 独自の色 |
| 原本参照の注記 | `.src`（赤字） | 図の埋め込み |

問題文は写真から起こしたテキストなので、**必ず `html.escape()` してから埋め込む。**

### 出力先

作業用の一時フォルダに書き出し、体裁を確認してからDriveの教材フォルダへ `rclone copy` する。
**リポジトリ内には置かない**（私用の教材のため）。

### 生成後の検査（必須・省略禁止）

**① 答えの漏れを機械で調べる。**

```bash
python ~/.claude/skills/quiz-generator/references/check_leak.py <出力HTML>
```

**漏れが1件でもあれば提示してはならない。** 該当箇所を言い換えて消し、再生成して0件にする。
（2026-08-08 に11節中10節で漏れていた。見出しに答えを書き、
関連問題の設問文に類似問題の答えを書いていた）

機械が拾えないのは**設問文のヒント**（「中心部ではなくどこに」のように選択肢を絞る書き方）。
これは自分で全設問を読んで確かめる。

**② 指定語句が模範解答に入っているかを調べる。**
設問で「『◯◯』の語を使って」と指定したなら、模範解答にその語が必ず入っていること。

**③ 体裁を目で見る。**
書き出したHTMLをブラウザで開き、崩れていないことを確認してから提示する。
**必ず巻末（解答一覧・解説）まで見ること**。
本文だけ見て提示すると、解説に混じった `**` などの記法ミスを見落とす。

印刷が必要なときはブラウザの「印刷 → PDFに保存」を使う。A4用のCSSはテンプレートに入っている。

### 解答・解説の構成

**巻末①　解答一覧**
```
p.13 ③(4) 問1（類似）： 答えのみ（簡潔に）
p.13 ③(4) 問2（関連）： 答えのみ（簡潔に）
...全問分
```

**巻末②　解説**
```
p.13 ③(4) 問1（類似）
```

## ステップ 6：問題記録 JSON の生成

HTML と同時に、作成した問題の記録を JSON ファイルとして出力する。
**mock-test-generator との連携および次回の重複回避に使う。**

### ファイル名
```
<HTMLと同じベース名>_log.json
例: 英語_Unit1-2_類似関連問題集_log.json
```

### JSON 構造

```json
{
  "created_at": "YYYY-MM-DD",
  "subject": "教科名",
  "unit": "単元名（例: Unit1-2）",
  "difficulty": { "類似": 0, "関連": 1 },
  "test_range": ["p.12-13", "p.14-15", "..."],
  "pages_scanned": ["p.12-13", "p.14-15", "..."],
  "visual_emphasis": [
    {
      "page": "p.12-13",
      "unit": "単元名",
      "can_do": "CAN-DOの内容（英語など明示されている場合）",
      "key_sentences": ["基本文1", "基本文2"],
      "emphasis_points": [
        "強調されていたポイント1",
        "強調されていたポイント2"
      ]
    }
  ],
  "problems": [
    {
      "source": "p.26 ③",
      "type": "類似",
      "difficulty": 0,
      "question_summary": "問題文の要約（30字程度）",
      "key_point": "問われているスキル・文法事項",
      "answer": "答え",
      "wrong_count": 1
    }
  ]
}
```

※ `visual_emphasis` は mock-test-generator が画像なしでコア項目を特定するために使う。
　 教科・出版社によって強調の形式が異なるため、テキスト固有の構造に合わせて柔軟に記録する。

※ `test_range` は**次のテストの出題範囲**（見開き単位）。`pages_scanned` は**実際に読んだページ**。
　 この2つは別物で、範囲の一部しか読んでいなければ `test_range` のほうが多くなる。
　 範囲から外すと決めたページは `visual_emphasis` の側に `"out_of_range": true` を付ける。

### 書いたら必ず通す（省略禁止）

```bash
python ~/.claude/skills/quiz-generator/references/check_coverage.py <log.json>
```

`test_range` の各ページが `pages_scanned` と `visual_emphasis` の両方に載っているかを1ページずつ照合する。
**`[NG]` が出たら、不足ページの写真を求めてJSONを作り直す。** そのまま模試に渡してはならない。
`pages_scanned` と `visual_emphasis` の件数が一致していても、読んだページ数自体が足りなければ
このチェックでしか見つからない（2026-08-08 に7枚渡されて2見開きしか読まなかった件）。

### wrong_count の設計思想

- **JSONにエントリが存在すること自体が「間違えた」の証拠**
- 指定された問題のみJSONに記録される（全問判読はしない）
- 指定されなかった問題のエントリは存在しない

### wrong_count の更新ルール

- 初回生成時は `wrong_count: 1`（生成＝1回間違えた事実）
- ユーザーが「また間違えた」「別バージョンを作って」と言った場合、
  対象問題の `wrong_count` を +1 してJSONを上書き保存する

| wrong_count | mock-test-generator での扱い |
|-------------|---------------------------|
| 1 | 重要項目として必ず含める |
| 2以上 | 必出項目として必ず1問以上含める |
| エントリなし | ①②の2軸のみで判断 |

### 生成方法

HTML 生成スクリプトの末尾に以下を追加する：

```python
import json
log = {
    "created_at": today,          # YYYY-MM-DD
    "subject": "教科名",
    "unit": "単元名",
    "difficulty": {"類似": 0, "関連": 1},
    "problems": [
        # 各問題のオブジェクトを配列で列挙（wrong_count: 1 で開始）
    ],
}
with open(log_path, "w", encoding="utf-8") as f:
    json.dump(log, f, ensure_ascii=False, indent=2)
```

**`ensure_ascii=False` を必ず付ける**（日本語がそのまま読める形で保存するため）。

## ステップ 7.5：answer-validator からの修正依頼への対応

### トリガー
- 「answer-validator 検証結果」を含むテキストが渡された場合
- 「✗の問題を修正して」「検証結果に基づいて修正して」などの言及がある場合

### 処理手順

**① 修正内容の確認**
渡された検証結果から ✗ の問題を全件抽出し、以下を確認する。

| 確認項目 | 内容 |
|---------|------|
| 問題番号 | どの問題が対象か |
| 修正種別 | 解き直し不一致 / 転記ミス のどちらか |
| 修正案 | answer-validator が提示した修正内容 |

**② 修正の適用**

- **解き直し不一致（答えが間違い）**：問題文・答え・解説を修正案に基づいて修正する
- **転記ミス（巻末①②の不一致）**：巻末①を正として巻末②を修正する

**③ HTML の再生成**

修正を適用してHTMLを再生成し、同じ場所に上書き保存する。
ファイル名は元のファイル名を維持する（`_fixed` などのサフィックスは付けない）。
**Driveへコピー済みの場合は、そちらも上書きする**（古い版が残らないようにする）。

**④ 再検証の案内**

```
修正済みHTMLを出力しました。
answer-validator で再検証することを推奨します。
```

## ステップ 8：レベルアップ版の生成（JSON 再投入）

過去に生成した log.json を渡して難易度を上げて作り直す場合のフロー。
画像の再アップロードは不要。

### トリガー
- 「log.jsonを使ってレベルを上げて」
- 「難易度を上げて作り直して」
- 「もっと難しいバージョンを作って」

### 質問フェーズ（必須・省略禁止）

JSON を受け取ったら、問題生成の前に以下を必ず聞く。

**Q1：対象タイプ**
```
類似問題・関連問題のどちらを作成しますか？
  1. 類似のみ
  2. 関連のみ
  3. 両方
```

**Q2：難易度**
```
難易度をいくつにしますか？

  -1　易しめ（穴埋め・選択肢あり、用語確認レベル）
   0　同等（類似問題の基本設定）
  +1　やや応用（語句指定あり記述・条件追加）
  +2　発展（複数知識の組み合わせ・自由記述）

現在の難易度：類似 = X、関連 = X（JSONの値を表示する）
```

両方の回答を受け取ってから生成に進む。

### 処理手順

**① JSON の読み取り**
- `subject` / `unit` / `visual_emphasis` / `problems[].key_point` を参照する
- 各問題の現在の `difficulty` を確認し、Q2 の回答と一緒に表示する

**② 問題の生成ルール**
- `key_point` は変えない（同じスキルを問う）
- 問題の形式・解答形式は前回と同じパターンを維持する
- 数値・語句・条件を変えて、指定難易度に合わせた内容にする
- 前回の `answer` と同じ答えになる問題は作らない

**③ JSON の更新**
- 対象問題の `difficulty` を指定された値に上書きする
- `wrong_count` を +1 する
- `created_at` を今日の日付に更新する
- ファイル名は `<ベース名>_lv<難易度>_log.json` で新規保存する
